# 偏见表达审阅包（Bias Review Report Pack）交付模板

更新时间：2026-05-19

这个文档用于把当前 Demo 从“一个可体验的小工具”推进到“可以人工交付、可以试收费、可以验证真实需求的服务”。

> 当前优先目标不是马上做账号、历史记录、批量后台或 SaaS，而是用 10 个真实样本验证：用户是否愿意把一段招聘 JD / 对外文案交给我们审阅，是否觉得报告有用，是否愿意为更完整的人工审阅包付 ¥99-299。

---

## 1. 服务定位

**一句话：**
为招聘 JD、雇主品牌文案、课程/招生活动介绍、营销/官网公开文案做一次“发布前包容性表达预检”，交付一份可转发给同事或客户的审阅报告。

**适合：**
- HR / 招聘小团队：招聘 JD、职位宣传、面试邀约、雇主品牌内容。
- 内容运营 / 市场文案：官网介绍、小红书/公众号文案、活动宣传。
- 教育培训 / 招生：课程介绍、招生文案、社群招募。
- NGO / DEI 相关组织：活动招募、倡议文案、志愿者文案。

**不适合：**
- 法律意见、合规结论、仲裁或申诉证据。
- 给个人贴标签或判断某个人是否“有偏见”。
- 完整公平性审计、组织 DEI 诊断或法律风险评估。
- 高度敏感、未经脱敏的个人隐私材料。

## 2. 试收费版本

### A. 免费样例审阅（验证期）

**目标：**换取真实样本与具体反馈。

- 用户提交：1 段旧招聘 JD / 公开文案，建议 300-1000 字。
- 交付：Demo 检测报告 + 简短人工备注。
- 换取反馈：
  1. 哪些提醒有用？
  2. 哪些是误报或不准？
  3. 是否会据此改文案？
  4. 如果这是更完整的报告，是否愿意付 ¥99-299？

### B. 偏见表达审阅包（¥99-299/次）

**目标：**验证用户是否为“省时间 + 可交付报告 + 人工复核”付小钱。

- 用户提交：1-3 段文本，总计建议 3000 字以内。
- 交付周期：24-48 小时。
- 交付物：
  - 总体风险摘要。
  - 逐段/逐句风险标注。
  - 每个风险点的原因说明。
  - 2-3 版更中性、包容的替代表达。
  - Markdown 或 PDF 报告。
  - 可选 10-15 分钟人工复核/说明。

### C. 小团队批量审阅（¥999-2999/批）

**只在 2-3 个用户反复要求批量时再推进。**

- 用户提交：10-30 条招聘 JD / 营销 / 课程文案。
- 交付周期：3-5 天。
- 交付物：
  - 批量风险汇总表。
  - 高风险表达清单。
  - 常见问题模式总结。
  - 品牌语气 / 中性表达 checklist。
  - 团队写作建议。

## 3. 用户提交说明模板

可以直接复制给潜在用户：

```text
如果你愿意帮我测试，可以发我一段旧招聘 JD / 公开文案。我会免费生成一份“包容性表达审阅报告”样例给你。

为了保护隐私，建议你先做这些处理：
1. 删除公司内部信息、真实姓名、手机号、邮箱、客户名。
2. 如果文案还没公开，不要发完整原文；可以只发你愿意测试的一小段。
3. 如果内容敏感，可以先自己在 Demo 里跑一遍，然后只把“分享包”或 Markdown 报告发给我。

我会看三件事：
- 是否存在容易引发性别刻板印象争议的表达；
- 是否有更中性、更稳妥的替代表达；
- 这份报告是否真的能帮你改文案。

说明：这不是法律/合规结论，也不替代人工判断；它是发布前的写作风险提示。
```

## 4. 审阅工作流

### Step 1：确认文本与边界

记录：
- 用户类型：HR / 内容运营 / 教育培训 / NGO / 其他。
- 文本场景：招聘 JD / 招生文案 / 营销文案 / AI 输出 / 其他。
- 文本是否已经公开。
- 是否有敏感信息、是否已脱敏。
- 用户希望优化的方向：更包容、更中性、更专业、更适合对外发布、更符合品牌语气。

### Step 2：用 Demo 跑第一轮报告

在 GitHub Pages Demo 或本地/后端模式中粘贴文本，得到：
- 总体风险分数。
- 风险案例。
- 命中线索。
- 改写建议。
- Markdown 报告或分享包。

### Step 3：人工复核

人工复核重点不是“证明工具都对”，而是把误报、语境和真正可改的地方分开。

检查：
- 命中的词是否真的在上下文中构成问题？
- 是否只是中性描述，被规则误报？
- 是否漏掉了明显的排他性表达？
- 替代表达是否改变了原意？
- 改写是否符合用户行业语气？
- 有无更轻、更自然的改法？

### Step 4：形成交付报告

报告建议包含：
1. 封面摘要。
2. 文本场景与审阅边界。
3. 总体风险等级。
4. 重点发现（3-5 条）。
5. 逐条风险标注。
6. 替代表达建议。
7. 可直接复制的改写版本。
8. 非法律/非合规结论说明。
9. 反馈问题与下一步建议。

### Step 5：收集反馈

交付后必须问：
- 你会不会采用其中至少 1 条改写？
- 哪条提醒最有用？
- 哪条是误报或不符合语境？
- 这份报告是否能转发给同事/老板/客户？
- 如果下次审阅 1-3 段类似文本，你愿意为节省时间和人工复核付 ¥99-299 吗？
- 如果有 10-30 条类似文本，你更希望提交什么格式？Word、Excel、Notion、飞书文档还是网页表单？

## 6. 人工复核 checklist

交付前逐项确认：

- [ ] 原文中的敏感信息已脱敏或用户明确同意用于审阅。
- [ ] 报告没有把用户或作者贴上“有偏见”的标签。
- [ ] 报告没有声称这是法律/合规结论。
- [ ] 每条风险都有具体原文片段或检测线索。
- [ ] 每条建议都解释了为什么更稳妥。
- [ ] 替代表达没有改变岗位要求、课程要求或业务事实。
- [ ] 至少提供 1 个可直接复制的改写版本。
- [ ] 报告结尾有反馈问题。
- [ ] 如果样本有价值，已记录到验证表格：用户类型、场景、有用性、误报、付费意愿。

## 7. 付费验证脚本

不要一开始强卖 SaaS。先在用户觉得报告有用之后轻问：

```text
如果以后你有类似的招聘 JD / 对外文案要发布，我可以帮你做一个更完整的“偏见表达审阅包”：
- 1-3 段文本；
- 逐条风险标注；
- 2-3 版替代表达；
- Markdown/PDF 报告；
- 可选 10-15 分钟人工说明。

我现在想验证一个很小的收费假设：这样的审阅包如果定价 ¥99-299/次，你会觉得合理吗？
如果不合理，是因为不够痛、报告不够可信、价格不合适，还是你更需要批量审阅？
```

如果对方回答“愿意但要批量”，追问：

```text
如果一次检查 10-30 条招聘/JD/营销文案，你最希望怎么提交？Excel、飞书表格、Notion、Word，还是网页表单？
你最想得到的是逐条修改建议，还是一个团队写作 checklist / 高风险表达清单？
```

## 8. 何时才做新功能

只有出现下面信号，才进入对应功能：

| 用户信号 | 下一步功能 |
|---|---|
| 2-3 个用户都说“我有很多条 JD 想一起跑” | 做最轻量批量检测：粘贴多段文本，用空行或 `---` 分隔 |
| 用户说“报告能不能给老板/客户看得更正式” | 做更稳健 PDF/HTML 报告模板 |
| 用户说“我想以后自己反复查” | 再考虑账号、历史记录、保存草稿 |
| 用户说“我们团队很多人都要用” | 再考虑团队空间和权限 |
| 用户说“我要接到自己的系统里” | 再考虑 API |

在这些信号出现前，不要过早做复杂后台。
